# OBS での検証 B1: 接続、V1〜V5 と仮決めの確定

## はじめに

計画の B1 の結果です。A2 では Chrome で確かめた前提を OBS の中で確かめ直しました。あわせて、要件 `.prompts/INIT.md` の 6 節で仮決めにしていた 4 つの事項を確かめ、確定させました。

## 検証環境

- ポータブル版の OBS 33.0.1。obs-browser 2.27.5、CEF 150.0.7871.252。起動の引数は `--remote-debugging-port=9235 --disable-updater --multi`
- プラグイン 0.0.1 (コミット bdb474b)。`.tmp/obs-33.0.1-portable/plugins/voice-spotlight/` に配置
- Discord のデスクトップアプリ。依頼者が 1 人で音声チャンネルに入った状態
- 操作と計測の道具は `.tmp/2026111103-uia-do.ps1` (UI Automation)、`2026111106-measure-apply.mjs` (適用から再表示までの計測)、`2026111108-set-portrait.ps1` (立ち絵の行の設定)、`2026111109-props-timing.ps1` (プロパティの画面の開閉の計測)

## 検証結果

### 接続

OBS の CEF 150 のブラウザーソースは、起動の引数を足さずに Discord のクライアント `ws://127.0.0.1:6463` に接続しました。`AUTHENTICATE`、`GET_CHANNEL`、5 種類のイベントの `SUBSCRIBE` が成功しました。A2 の Chrome 157 で起きた `net::ERR_BLOCKED_BY_LOCAL_NETWORK_ACCESS_CHECKS` は起きませんでした。記録は `.logs/2026111104-obs-cdp-trace-redacted.log` です。アクセストークンの行は除いています。

### 土台

| 確認 | 結果 |
| --- | --- |
| プラグインの読み込み | ログに `[voice-spotlight] plugin loaded successfully (version 0.0.1)` と `Dock registered successfully` |
| ドックの「新規作成…」 | URL の貼り付けでブラウザーソース「Discordの通話」が作られ、ドックで選ばれた |
| ユーザー ID の欄 | `abc` を設定しても値は空のまま |
| ドックの表示の状態 | 再起動の後も表示された |
| 終了 | 2 回とも `Number of memory leaks: 0`。`crashes/` は空 |

### V1: 発話中のクラス

依頼者に 60 秒間、話す・黙るを繰り返してもらいました。発話の開始は 5 回で、5 回とも `li` の `wrapper_speaking` と `img` の `Voice_avatarSpeaking__lE+4m` が同時に付き外れしました。A2 と同じ結果です。

### V2・V4: 立ち絵の表示と、適用から再表示までの時間

ドックで依頼者のユーザー ID に立ち絵を登録しました。毎回、待機中の明るさを 50% と 51% で交互に変えてから「適用」を押しました。ブラウザーソースは、設定が前回と同じだとページを作り直さない可能性があるためです。終点は、新しいページで依頼者の `li` の `img` が `content: url("data:...")` を持ち、新しい明るさの `filter` になった時点です。計測の値は、クリックを送る PowerShell の起動の約 0.5 秒を含みます。

| 条件 | 注入された CSS | 立ち絵の描画 | 回数 | 時間 |
| --- | --- | --- | --- | --- |
| 100 x 200 の png 1 枚 | 1,974 文字 | 75 x 150 | 5 | 1,252〜1,416 ms |
| 400 x 866 の png 4 枚、合計 4,160,856 バイト | 5,550,169 文字 | 69.3 x 150 | 4 | 1,367〜1,462 ms |

5 回とも、適用の前のページの接続先は消え、新しい接続先で終点に達しました。4 枚の条件の 1 回目は、前の計測の最後と同じ値を設定したため、適用の前のページで終点の条件を満たしました。この回は無効として表から除きました。

### V3: 画像の大きさの上限

4 枚、合計 4,160,856 バイトの立ち絵を適用した状態で確かめました。1 枚あたりの上限は 1,048,576 バイト、合計の上限は 4,194,304 バイトです。

| 確定の条件 | 結果 |
| --- | --- |
| 立ち絵が表示される | 表示された (V4 の表) |
| プロパティの画面を開いて閉じられる | 3 回とも開閉できた。開くまで 616〜767 ms (PowerShell の起動を含む)、閉じるまで 361〜455 ms。テキスト欄には 5,550,169 文字が入っていた |
| シーンコレクションの保存と読み込みの後も表示される | OBS を終了し、画像のファイルを別のフォルダーに移してから再起動した。立ち絵は表示され、注入された CSS は 5,550,169 文字だった |

終了後のシーンコレクションのファイルは 11,110,850 バイトでした。ブラウザーソースの `settings.css` と、プラグインの `private_settings.voice_spotlight.applied_css` に、同じ 5,550,169 文字が入っていました。

画像のファイルが無い状態で「適用」を押すと、適用は止まり、ドックに「立ち絵 1: 画像のファイルが見つかりません: (パス)」と表示されました。

### V5: 設定の保存先

| 操作 | 結果 |
| --- | --- |
| OBS の再起動 | ドックのソースの選択は空に戻った。「Discordの通話」を選び直すと、立ち絵 4 行と待機中の明るさ 51% が復元された |
| シーンコレクションの切り替え | 依頼者が手で操作した。新しいシーンコレクション「検証2」に切り替えると、ドックのソースの欄は空で、一覧に「Discordの通話」は無かった。「無題」に戻して選び直すと、立ち絵 4 行と 51% が復元された。「検証2」のシーンのファイルに、プラグインの設定は無かった |
| ソースの複製 | 依頼者が手で操作したところ、「貼り付け (複製)」が選べなかった。obs-browser の `obs-browser-plugin.cpp` の 456〜457 行で、ブラウザーソースの `output_flags` に `OBS_SOURCE_DO_NOT_DUPLICATE` が付いている |

### 自動操作の問題

UI Automation とマウスの操作で、OBS に何度もフォーカスが移りました。依頼者は並行して別の作業をしており、そのたびにフォーカスを戻していました。ソースの URL の末尾に `su` の 2 文字が入りました。依頼者の入力が入ったものと推定しています。`streamer_avatar_first=falsesu` は `true` ではないため、表示には影響しません。ドックのほかの値は、UI Automation で読み、設定した値と一致することを確かめました。

## 考察

- 仮決めの 4 つの事項は、確定の条件を満たしたと考えています。
- 適用から再表示までの約 1.4 秒の途切れは、適用ボタンを押したときにしか起きません。そのため、OBS のプレビューで確かめる方式のままで、配信中の調整にも使えると判断しました。立ち絵の有無と大きさは、途切れの長さをほとんど変えないと推測します。
- ソースを複製できないため、複製に関する要件の確認は不要だと考えています。
- シーンのファイルの大きさは、`applied_css` をハッシュ値に置き換えれば約半分になると推測します。課題 5dt.10 に登録しました。
- ドックの操作の確認を自動で行うと、依頼者の並行作業を妨げます。フォーカスが要る確認は、依頼者に手で行ってもらうか、依頼者が PC を使わない時間に行うべきだと考えています。
