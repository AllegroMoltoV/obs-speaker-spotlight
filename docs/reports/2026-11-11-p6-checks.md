# P6: 1 人 1 ソースと自動の反映の OBS での確認

## はじめに

依頼者の使い心地の指摘に対応した P1〜P5 (1 人 1 ソース、約 2 秒後の自動の反映、ドックのプレビュー、元に戻す・CSS のコピー・生成した CSS の欄の削除、ダイアログの日本語のボタン) を、OBS で確かめた結果です。課題は 5dt.18 です。依頼者が PC を使わない時間に、UI Automation とキー入力でドックを操作しました。

## 検証環境

- ポータブル版の OBS 33.0.1。プラグインはコミット 7c72b90 のビルド
- 確認の時点で、音声チャンネルの参加者は 0 人
- 道具は `.tmp/2026111128-watch-targets.mjs` (ページの作り直しの記録)、`2026111129-type-into.ps1` (キー入力)、`2026111130-dump-style.mjs` (注入された CSS の読み取り)、`2026111131-choose-portrait.ps1` (立ち絵の選択)、`2026111132-capture-dock.ps1` (ドックの画像の保存)。ログは `.logs/2026111129`〜`2026111133`

## 検証結果

| 確認 | 結果 |
| --- | --- |
| ソースを選ぶ前のドック | ソースの選択と「新規作成…」だけが有効だった |
| 新規作成の URL の初期値 | 選んでいたソースの URL (435 文字) と一致した |
| 自動の反映 | ユーザー ID の 18 文字をキー入力すると「反映待ち」と表示され、入力の終わりから約 2 秒後に「「Discordの通話 2」に反映しました。」に変わった。ページの作り直しは 1 回で、注入された CSS は 80 文字から 1,141 文字になった |
| 1 人以外を隠す CSS | `.voice_state` に `display: none`、`.voice_state[data-userid="<ID>"]` に `display: flex` が出ていた。管理範囲の外にある元の CSS は残っていた |
| ID を消したとき | 約 2 秒後に「「Discordの通話 2」から発話スポットライトのCSSを外しました。」と表示され、注入された CSS は 80 文字に戻った |
| 反映待ちの間にソースを切り替えたとき | 入力の終わりから約 1.3 秒で別のソースを選んだ。元のソースに書き込まれ「反映しました」と表示された。切り替え先のソースの CSS は変わらなかった |
| 立ち絵の選択 | 依頼者の立ち絵 (4000 x 6800) を選ぶと「埋め込み 99 KB (WebP)」と表示され、約 2 秒後に反映された |
| 値を変えてすぐ戻したとき | 待機中の明るさを 60% にして 0.5 秒後に 50% へ戻した。「反映済みです」と表示され、ページは作り直されなかった |
| 元の画像が無くなった後 | 一時的なコピーを選んでから削除し、高さを 300px に変えた。エラーは出ずに反映され、終了後の CSS に `height: 300px` があった |
| プリセット | 名前の入力のボタンは「OK」「キャンセル」。保存された内容は `{"avatar_height":427}` で、ID と立ち絵を含まなかった。削除の確認のボタンは「はい」「いいえ」 |
| 保存の形 | 立ち絵は private settings の `portrait` に WebP 706 x 1200、base64 134,616 文字で保存されていた。CSS は 135,985 文字 |
| 終了 | `Number of memory leaks: 0` |

ドックの画面の画像は `.tmp/2026111133-dock-preview.png` に保存しました。開発のセッションは中身を見ていません。

古い版の検証で使ったソースの private settings に、今の版が読まない古いキー (`portraits`、`previous_css` など) が残っていました。未公開の版の検証環境にだけ残るものです。

## 考察

- 自動の反映と、同じ CSS を書き込まない判定は、意図どおりに動いていると考えています。
- 立ち絵を選んだ時点の保存により、元のファイルの移動や削除に左右されないことを確かめられたと考えています。
