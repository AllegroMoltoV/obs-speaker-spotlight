# 立ち絵を最大 2160px で保存したときの大きさと処理時間

## はじめに

課題 obs-voice-spotlight-5dt.22 の計測の結果です。表示の高さの上限を 600px から 2160px に上げ、保存する立ち絵の高さの上限 `EMBED_HEIGHT_LIMIT` を 1200px から 2160px に変えました。立ち絵は元より大きくせず、高さ 2160px を上限に縮小して、WebP の画質 90 で書き出します。1 枚 1,048,576 バイトを超えるときの段は変えていません。段は倍率 1・0.75・0.5 を画質 90 で試し、続けて倍率 0.5 で画質 75・60・50 を試します。

この計測では、依頼者の立ち絵 7 枚が上限の 2160px で 1 枚の上限に収まることと、画像を選んでから保存するまでの時間を確かめます。

## 検証環境

- Windows 11、`cmake --build --preset windows-ci-x64` で作った RelWithDebInfo の実行ファイル
- Qt は `.deps/obs-deps-qt6-2026-10-23-x64` のもの。`QT_PLUGIN_PATH` に同じ Qt の `plugins` を、`PATH` に `bin` を渡して実行した
- 画像は依頼者が貸した立ち絵 7 枚。本文ではサンプル 1〜7 と呼ぶ。`docs/reports/2026-11-11-portrait-optimization.md` と同じ 7 枚で、サンプル 1〜3 はネットワーク上の共有フォルダー、サンプル 4〜7 はローカルのディスクから読んだ

## 検証方法

計測用の実行ファイル `speaker-spotlight-image-bench` を使いました。ソースは `tests/image-bench.cpp` で、プラグインと同じ `src/portrait-image.cpp` の関数を使います。

各サンプルについて、元の画像を 1 回読み、高さ 2160px・1620px・1080px に縮小しました。縮小した画像を WebP の画質 100・90・80・75 と PNG で書き出し、縮小と書き出しを 3 回ずつ計って中央値を採りました。続けて、プラグインの段の列で書き出した大きさから、プラグインと同じ `choose_embedding()` で選ばれる段を求めました。最後に、プラグインが画像を選んだときに呼ぶ `embed_portrait_file()` を 3 回実行し、読み込みから段の選択と書き出しまでの時間の中央値を計りました。この時間の計測は今回 `tests/image-bench.cpp` に足しました。

実行のコマンドは次のとおりです。見た目の確認用の画像は書き出していません。

```powershell
$qt = "D:\work\obs-voice-spotlight\.deps\obs-deps-qt6-2026-10-23-x64"
$env:PATH = "$qt\bin;$env:PATH"
$env:QT_PLUGIN_PATH = "$qt\plugins"
& build_x64\RelWithDebInfo\speaker-spotlight-image-bench.exe .tmp\2026111118-sample-portraits.txt
```

生の出力は `.logs/2026111136-image-bench-2160.log` です。

## 考察

上限を 2160px に上げても、依頼者の 7 枚は画質 90 の 1 段目で 1 枚の上限に収まり、最大でも上限の約 3 割に留まると考えています。今回の 7 枚では段を引き下げる経路を通っていないため、その経路の正しさは単体テストの `test_choose_embedding` に依っています。

保存の時間は 1 枚 0.2〜0.6 秒で、画像を選んだ操作の直後に OBS の UI のスレッドで行う処理として許容できる範囲だと考えています。ただし、遅い PC ではこの値より長くなると推測します。

元の高さが 1620px 以上 2160px 未満の画像では、2 段目が 1 段目と同じ出力になります。1 段目で上限を超える画像なら、2 段目は大きさを減らさずに書き出しの時間だけを使うと考えています。今回の 7 枚は 1 段目で収まったため影響はありません。段の選び方は今回の変更の対象外としました。

PNG で書き出す環境では、7 枚中 4 枚が倍率を下げた段で保存されると推測します。この環境は Windows の OBS の Qt では起きないため、確かめていません。
