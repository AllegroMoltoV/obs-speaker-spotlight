# ブラウザーソースの大きさの自動の調整: ローカルのページでの計測

## はじめに

課題 obs-voice-spotlight-5dt.23 の計測の結果です。反映のときに、ブラウザーソースの幅と高さを中身の外寸に合わせるようにしました。大きさは `src/core/voice-style.cpp` の `content_size()` で、次のように求めます。

| 表示するもの | 幅 | 高さ |
| --- | --- | --- |
| 立ち絵 | 高さの設定 × 保存した画像の幅 ÷ 保存した画像の高さ、を切り上げた値 | 高さの設定 |
| アバター | 高さの設定 + 緑の枠の分 | 高さの設定 + 緑の枠の分 |

この計測では、緑の枠の分を決め、生成した CSS で中身がソースの左上から隙間なく並び、外寸がソースの大きさに収まることを確かめます。OBS は起動していません。

## 背景

StreamKit のアバターの `img` には 3px の枠があり、発話中に枠の色が緑になります。枠が要素の外寸に含まれる量は CSS の `box-sizing` で変わります。また、StreamKit の `body`・一覧を包む `div`・`ul`・`li` には余白があり得ます。そこで生成する CSS で、次を指定しました。

- `body`、`.voice_container`、`.voice_states`、表示する人の `li` の `margin` と `padding` を 0 にする
- アバターの `img` に `box-sizing: content-box` と `border-width: 3px` を指定する。外寸は幅と高さの設定に上下左右の枠を足した値になる
- 名前を常に隠すため、`li` の `gap` を削除する

`img` は `display: flex` の `li` の子のため、行の高さの基準線の下の隙間は生じません。

## 検証環境

- Chrome 157.0.8103.39 のヘッドレス。起動の引数は `--headless=new --remote-debugging-port=9336` と、専用の `--user-data-dir` の `.tmp/2026111138-chrome-profile`
- ページは A4-3 で作ったローカルのページ `.tmp/2026111021-local-page.html`。保存した StreamKit の DOM とスタイルシートから作ったもの
- CSS は `build_x64/RelWithDebInfo/speaker-spotlight-css-dump.exe` で、作業ツリーの `generate_css()` から生成した

## 検証方法

`speaker-spotlight-css-dump` に高さと PNG のファイルを渡すと、立ち絵なしの CSS と、PNG ごとの立ち絵ありの CSS を書きます。あわせて、`content_size()` で求めたソースの幅と高さを出します。PNG は `.tmp/2026111141-make-png.mjs` で作った、縦長の 333 x 1000 と横長の 1000 x 333 です。縦横比を割り切れない値にし、幅の切り上げを確かめられるようにしました。

計測は `.tmp/2026111144-size-run.mjs` で行いました。高さの設定 20px・150px・2160px のそれぞれで、立ち絵なし・縦長・横長の 3 通りを計測します。`.tmp/2026111139-size-check.mjs` が、ページの大きさを `content_size()` の幅と高さにして読み込み、OBS の既定の CSS と生成した CSS を `style` 要素として `head` に足します。obs-browser と同じ注入の方法です。続けて、表示する人の `li` と `img` の `getBoundingClientRect` と、文書の `scrollWidth` と `scrollHeight` を読みます。読み取りは待機中と、`li` に `wrapper_speaking` を付けた発話中の 2 回です。

表示する人は、ローカルのページの参加者のうち、ユーザー ID が 200000000000000002 の参加者にしました。依頼者のユーザー ID は使っていません。

判定の条件は次のとおりです。

- 表示されている `li` が 1 つだけである
- `li` の位置が 0, 0 で、幅と高さがページの大きさと一致する
- `img` の位置が 0, 0 で、高さが中身の高さと一致する
- `img` の幅が、立ち絵なら 高さの設定 × 縦横比 と 1/64px 以内で一致し、ページの幅以下で、差が 1px 未満である。アバターならページの幅と一致する
- 文書の大きさがページの大きさと一致する

1/64px の差を許したのは、Chrome が要素を 1/64px の単位で配置するためです。

実行のコマンドは次のとおりです。

```bash
node .tmp/2026111144-size-run.mjs 9336
```

生の出力は `.logs/2026111138-size-check.log` です。

## 検証結果

18 件すべてが判定の条件を満たしました。待機中と発話中で、`li` と `img` の位置と大きさは同じでした。

| 20px | 縦長の立ち絵 | 7 x 20 | 0, 0, 7 x 20 | 0, 0, 6.656 x 20 | 7 x 20 |
| 20px | 横長の立ち絵 | 61 x 20 | 0, 0, 61 x 20 | 0, 0, 60.047 x 20 | 61 x 20 |
| 150px | アバター | 156 x 156 | 0, 0, 156 x 156 | 0, 0, 156 x 156 | 156 x 156 |
| 150px | 縦長の立ち絵 | 50 x 150 | 0, 0, 50 x 150 | 0, 0, 49.938 x 150 | 50 x 150 |
| 150px | 横長の立ち絵 | 451 x 150 | 0, 0, 451 x 150 | 0, 0, 450.438 x 150 | 451 x 150 |

`li` の祖先の `html`、`body`、2 つの `div`、`ul` は、9 通りとも位置が 0, 0 で、大きさがページと一致し、`margin` と `padding` が 0px でした。

アバターの `img` の枠は、待機中が `3px solid rgba(0, 0, 0, 0)`、発話中が `3px solid rgb(59, 165, 59)` でした。`box-sizing` は `content-box` です。立ち絵の `img` の枠は 0px でした。

## 考察

アバターの外寸は、枠の色が透明の待機中も、緑の発話中も、高さの設定に 6px を足した値でした。そのため、緑の枠の分は上下左右の 3px の和の 6px で決めてよいと考えています。枠の幅と `box-sizing` は生成する CSS で指定しているため、StreamKit のスタイルシートが変わっても、この値は変わらないと考えています。

立ち絵の幅は、ソースの幅より最大で 1px 弱小さくなります。右端に 1px 未満の透明な列が残りますが、背景が透明のため見た目に影響しないと考えています。

この計測は Chrome 157 で行いました。OBS 33.0.1 の CEF での配置と、ソースの大きさを変えたときにページを作り直さないことは、課題 obs-voice-spotlight-5dt.24 で確かめる必要があります。
