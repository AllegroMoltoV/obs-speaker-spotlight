# 土台の移植とローカルのビルド

実施日: 2026-11-10
対象の課題: obs-voice-spotlight-5dt.2 (A1)

## はじめに

兄弟プラグイン obs-comment-skin から、ビルドの仕組みと OBS に依存しない部品を写し、ドックだけを持つプラグイン `voice-spotlight` 0.0.1 を作りました。ローカルのビルドと単体テストは通りました。ポータブル版 OBS 33.0.1 を展開し、プラグインを配置しました。OBS は起動していません。読み込みとドックの表示は B1 で確かめます。

## 移植の方法

流用元は `D:/work/obs-comment-skin` のコミット 255a683 です。作業の時点で comment-skin の HEAD は bad2889 に進んでいました。255a683 からの差分は、プレビューのパネル、ドック、`docs/` だけです。流用元の作業ツリーに触れないよう、`git archive` で 255a683 を `.tmp/2026111003-comment-skin-255a683/` に取り出し、そこから写しました。

`build-aux/run-clang-format`、`run-gersemi`、`run-swift-format` は、comment-skin の git ではシンボリックリンク (モード 120000) です。この PC では `core.symlinks` が false のため、リンク先の名前 `.run-format.zsh` だけを書いたファイルとして置きました。コミットの際に、git のインデックスでモード 120000 に設定しています。`.github/scripts/` の 4 つのスクリプトと `build-aux/.run-format.zsh` にも、comment-skin と同じく実行の属性 (モード 100755) を付けています。

### 新たに書いたもの

| ファイル | 内容 |
| --- | --- |
| `src/voice-spotlight-dock.*` | ドック |

ドックが持つ操作は次のとおりです。

- ブラウザーソースの選択。候補は型 ID が `browser_source` のソースだけで、一覧を開くときとシーンコレクションの切り替えで作り直す
- URL の警告。選んだソースの `url` が `streamkit.discord.com` あるいは `streamkit.discordapp.com` の `/overlay/voice/<数字>/<数字>` でなければ表示する。適用は止めない
- 適用。`generate_css()` の結果を管理範囲に書く
- 元に戻す。プラグインが最初に書き換える前の `css` に戻す
- ファイルの CSS を書き込む (検証用)。選んだファイルの中身を管理範囲に書く。B2 で削除する

プリセットとスタイルの項目の UI はドックに置いていません。`src/preset-store.*`、`src/settings-widgets.*`、`src/create-source-dialog.*` はビルドに含まれますが、ドックからは使っていません。

### 整形

comment-skin と同じ方法で確かめました。

| コマンド | 対象 | 結果 |
| --- | --- | --- |
| Visual Studio 2022 に同梱の clang-format 19.1.5 で `--dry-run --Werror` | `src/` と `src/core/` の `.cpp` と `.h`、`tests/core-tests.cpp` | 終了コード 0 |

## 考察

helpers.cmake の判定の差は、gersemi の版による整形の規則の違いだと推測します。macOS の helpers.cmake が obs-loudness-balance-monitor と同一であり、同じ書き方のファイルが CI を通っていれば、CI の版では問題にならないと考えています。obs-loudness-balance-monitor の CI の実行結果は、今回は確かめていません。
