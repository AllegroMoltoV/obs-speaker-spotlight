# Q4: 名前の削除・高さの上限・大きさの自動の調整の OBS での確認

## はじめに

依頼者の 2 回目の指摘に対応した Q1〜Q3 (名前の削除、高さの上限 2160px、ブラウザーソースの大きさの自動の調整) を、OBS で確かめた結果です。課題は 5dt.24 です。依頼者が PC を使わない時間に、UI Automation とキー入力でドックを操作しました。

## 検証環境

- ポータブル版の OBS 33.0.1。プラグインはコミット b98ee22 のビルド
- 依頼者が 1 人で音声チャンネルに入った状態。参加者は 1 人
- 立ち絵は依頼者から借りた 1 枚。この文書ではサンプル 6 と呼ぶ。元の寸法は 4000 x 6800
- 道具は `.tmp/2026111137-probe-size.mjs` (ページの大きさと要素の外寸の計測)、`2026111128-watch-targets.mjs` (ページの作り直しの記録)、`2026111129-type-into.ps1`、`2026111131-choose-portrait.ps1`。ログは `.logs/2026111139-q4-height.log`

## 検証結果

| 確認 | 結果 |
| --- | --- |
| ドックの区画 | 「表示する人」「プレビュー」「明るさ」「発話中の表示」「立ち絵とアイコン」で、名前の区画は無かった |
| アバター (立ち絵なし、高さ 150px) | ソースは 156 x 156 になった。`li` と `img` はどちらも (0, 0) から 156 x 156。名前は表示されず、枠は `3px rgba(0, 0, 0, 0)` |
| 立ち絵 (高さ 150px) | 立ち絵は 1271 x 2160 で保存され、ドックに「埋め込み 220 KB (WebP)」と出た。ソースは 89 x 150 になった。`li` は (0, 0) から 89 x 150、`img` は 88.25 x 150 |
| 高さを 2160px にしたとき | ページの作り直しは 1 回だった。ソースは 1271 x 2160 になり、`li` と `img` はどちらも (0, 0) から 1271 x 2160 |
| ID を空にしたとき | 「「Discordの通話 2」から発話スポットライトのCSSを外しました。」と表示され、注入された CSS は 80 文字に戻った。ソースの大きさは 1271 x 2160 のまま変わらなかった |
| 終了 | `Number of memory leaks: 0` |

どの場合も、文書の大きさ (`scrollWidth` と `scrollHeight`) はソースの大きさと一致しました。

## 考察

- ソースの大きさの自動の調整は、OBS の CEF でも、ローカルのページでの計測 (`docs/reports/2026-11-11-source-size.md`) と同じく、切れも余白も無く働いていると考えています。
- 高さを変えると CSS と大きさが同時に変わり、ページは 1 回だけ作り直されます。2 回の書き込みにならないことを確かめられたと考えています。

## 未確認

- ソースの大きさを手で変えた後に、CSS が変わらない操作で大きさだけが戻り、ページが作り直されないこと。プロパティの画面の幅の欄を UI Automation で操作できず、3 回失敗したため打ち切った。この処理は単体テスト `test_size_update` と、obs-browser の `obs-browser-source.cpp` の 520〜539 行の読み取りで確かめている
- 発話中の緑の枠を含めた外寸。確認の間に発話が無かった。ローカルのページでは、発話中も外寸が同じことを確かめている
- 参加者が 2 人以上の通話での表示。B3 で確かめる
